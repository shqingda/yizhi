# 用户体验改进计划（草案）

更新日期：2026-09-29。当前范围调整：保留本机编辑、自动保存、多份草稿、恢复点、JSON 备份、预览与导出。按用户要求移除登录/注册、云端同步和公开分享；第三阶段取消，不再安排邮件配置或跨设备同步验收。首次打开直接显示样例，清空浏览器数据后恢复样例。

以下阶段勾选与实施记录保留为历史记录；涉及云端、账号、首次选择弹窗的条目已不属于当前版本。

目标：让用户放心修改简历，清楚知道内容保存在哪里，能够准确预览、导出和分享，并降低首次填写与手机操作的成本。

本计划已进入实施。勾选表示已实现并通过本轮相应代码、自动化或浏览器检查；不表示所有设备验收完成。已执行与尚未执行的验证见文末记录。

## 1. 范围与顺序

保持现有简洁编辑器的方向，按完整使用流程分批交付。先解决内容安全和操作反馈，再完善填写效率与外部分享。

| 阶段 | 用户得到什么 | 主要依赖 |
| --- | --- | --- |
| 第一阶段：放心保存 | 看得见保存状态，不会因重复请求或旧草稿误覆盖新内容 | 无 |
| 第二阶段：放心修改与导出 | 删除能撤销，导入可恢复，预览和导出符合预期 | 第一阶段 |
| 第三阶段：可控分享 | 明确发布哪一版，复制链接，随时停止分享 | 第一阶段；所有者授权与发布数据隔离 |
| 第四阶段：高效填写 | 空白新建、经历折叠复制、日期辅助、照片处理 | 第二阶段的恢复机制 |
| 第五阶段：手机与无障碍完善 | 手机上顺畅编辑和阅读，键盘也能完成操作 | 前述交互结构稳定 |

第一轮交付第一、二阶段：常驻保存状态、删除可撤销、导入前备份、当前稿预览、准确的导出选项，以及支撑这些体验的保存修复。分享面板单独作为下一轮，避免只增加复制按钮而保留发布与权限上的歧义。

无障碍标签、焦点管理和错误提示随每阶段一起补；第五阶段负责整体验收。暂不安排 AI 润色、简历评分、大量模板、协作编辑、完整离线应用和复杂账号体系。

## 2. 第一阶段：放心保存

### 实施内容

- [x] 按后续反馈保持单行顶栏；本机与云端状态放在“更多”，异常时入口显示提示点。
- [x] 区分“保存中”“已保存到本机”“已同步云端”“同步失败”“本机保存失败”“存在冲突”；错误提供对应操作。
- [x] 最近保存时间使用本地时间或相对时间，并提供完整时间说明。
- [x] 按内容变化触发保存，避免保存响应更新版本后再次触发空保存；同一简历的云端请求串行处理。
- [x] 本地草稿记录稳定简历标识、基础云端版本和保存时间；公开地址不再承担草稿身份。
- [x] 兼容现有草稿键与旧数据。缺少基础版本的旧草稿必须先识别差异，不能直接配上最新云端版本自动覆盖。
- [x] 数据库通过版本条件完成原子更新；正常保存明确携带基础版本，强制覆盖作为单独的用户操作处理。
- [x] 处理存储容量不足和不可用；路由切换、页面隐藏时尽力写入本地待保存内容，不依赖退出时完成云端请求。
- [x] 冲突时停止自动覆盖，保留本地和云端两份内容，允许查看差异、采用云端或明确覆盖；替换前保留可恢复副本。
- [x] 网络恢复后提供重试，并识别重试期间的新编辑，避免旧响应把新修改标记成“已同步”。

### 验收标准

1. 停止编辑且同步完成后不再周期性发送保存请求；快速连续输入最终保存最新内容。
2. 断网与本地写入失败呈现不同状态；写入失败不能显示成功，用户仍可下载备份。
3. 两个客户端基于同一版本保存时，后一笔写入收到冲突，不静默覆盖。
4. 旧本地草稿遇到更新的云端内容时，两份内容都可取回；本地成功保存的末次修改刷新后仍存在。
5. 编辑后立即切换到站内预览，当前内容不会因防抖计时器取消而消失。

主要涉及：`src/app/hooks/useResume.ts`、`src/app/lib/storage.ts`、`src/app/lib/api.ts`、`src/shared/sync.ts`、`src/worker/index.ts`、`src/db/schema.ts` 与迁移文件。

### 预览与导出

- [x] 带图标的“编辑模式 / 预览模式”切换直接展示当前稿；独立“网页预览”入口进入分享预览与发布。
- [x] 预览提供适应宽度、100% 和放大缩小；预览缩放不改变导出尺寸。
- [x] 导出选项明确为“A4 PDF”和“长页 PDF（图片内容）”；在真正支持 PNG/JPG 前不使用“导出长图”的含糊文案。
- [x] A4 导出首次使用时提供简短打印说明：选择另存为 PDF、A4、正确缩放和关闭页眉页脚。可关闭并记住偏好。
- [x] 默认文件名使用“姓名-目标职位-简历.pdf”，缺失字段有合理回退，支持修改并处理不适合文件名的字符。
- [x] 导出前提示明确问题，例如姓名为空、联系方式全隐藏、已检测到内容溢出；普通提醒允许继续导出。
- [x] 导出失败保留编辑状态，提供重试；按后续反馈不显示“已打开打印对话框”等冗余成功通知。

### 验收标准

1. 删除、排序和导入后可恢复；撤销恢复后的内容也正常保存。
2. 导入无效文件、取消导入或创建备份失败，都不会覆盖原稿。
3. 离线也能预览并导出当前稿；刚修改就预览能看到最新内容。
4. 下载格式、文件扩展名和按钮文案一致；取消打印后仍能继续编辑。
5. 单页、多页、长经历、图片与长网址样例经过真实浏览器打印检查，无意外裁切与空白页。

主要涉及：`src/app/pages/EditorPage.tsx`、编辑表单与列表控件、`src/app/lib/storage.ts`、`src/app/lib/exportResume.ts`、`src/app/hooks/useResumeFit.ts`。

## 4. 第三阶段：可控分享

默认方案是“云端保存草稿，用户明确发布公开版本”。后续编辑保存草稿，点击“更新分享内容”才改变访客看到的内容。该方案涉及现有行为变化，旧记录原样保留且不自动发布；旧地址需管理员核实归属后授权原所有者重新发布。

### 实施内容

- [x] 建立编辑者身份与简历归属校验，保护写入、完整草稿读取和简历列表；采用多人独立账号，Supabase 邮箱密码认证；邮件服务配置后还需端到端验收。
- [x] 公开页只读取发布快照，服务端移除隐藏字段和栏目；撤回后旧链接不再返回简历数据。
- [x] 增加分享面板：完整链接、复制按钮、已发布版本时间、“草稿有未发布修改”和“更新分享内容”。
- [x] 首次发布前展示访客可见内容；发布失败不显示成功。
- [x] 公开地址采用“输入 → 校验 → 确认”，检查字符、占用情况，并说明修改后旧链接的处理结果。
- [x] 支持停止分享与重新发布，明确提示已下载的文件无法撤回。
- [x] 区分网络错误、链接不存在和分享已撤回；网络错误提供重试。
- [x] 公开访客不显示容易误解的“编辑这份简历”入口；拥有者才获得编辑入口。

### 验收标准

1. 编辑未发布内容时，已分享页面保持原版本；主动更新后访客看到新版本。
2. 使用独立浏览器会话验证，复制链接能看到所发布的内容，不依赖本机草稿。
3. 隐藏内容不出现在公开接口响应中；非所有者不能修改简历或读取完整草稿。
4. 停止分享后旧链接失效；地址冲突不改变原链接，也不影响草稿。
5. 旧数据和链接的迁移有可回退方案，不把全部历史记录默认视为可公开发布。

主要涉及：Worker 接口、数据库结构与迁移、`src/app/pages/PublicResumePage.tsx`、编辑器分享面板、API 客户端。

## 7. 交付与验证方式

每批改动围绕一段完整流程交付，更新使用指南和架构边界。文案、按钮标签等低影响改动以人工检查为主；新增自动化测试聚焦数据保存、恢复、并发和访问权限。

| 检查层次 | 覆盖内容 |
| --- | --- |
| 逻辑与 Hook 测试 | 保存去重、请求顺序、旧草稿迁移、冲突恢复、撤销重做、存储失败 |
| D1 集成测试 | 条件更新、两个客户端并发保存、公开地址冲突、发布与撤回 |
| 浏览器流程 | 新建 → 填写 → 删除与恢复 → 刷新 → 预览 → 导出；断网 → 编辑 → 恢复网络 |
| 公开访客流程 | 发布 → 独立会话访问 → 草稿修改 → 更新发布 → 撤回 |
| 排版与手动检查 | 单页、多页、超长内容、照片、中文字体、手机输入、键盘和打印 |

代码批次运行 `pnpm check`；涉及真实浏览器、打印或 D1 的行为必须补对应验证，不能只依赖现有 jsdom 测试。实际验证后再在本计划勾选完成项。

已确定多人独立账号、邮箱密码登录。上线前按 accounts-and-sharing.md 配置认证邮件，并安排旧链接迁移。

仓库当前的依赖升级改动独立核验和提交，避免与体验功能混成同一批变更。本轮改动尚未提交或部署；原有依赖升级文件保持独立，不纳入体验实现的代码说明。
