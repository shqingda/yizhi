## 1. 使用简历编辑器

| 地址 | 用途 |
| --- | --- |
| `/` 或 `/editor` | 编辑基本信息、经历、技能等内容，调整版式。 |
| `/resume` | 预览当前浏览器中正在编辑的简历。 |

推荐的操作顺序：

1. 首次进入直接显示样例模板；已有本机草稿会自动继续。可在“管理简历”中新建空白简历。
2. 填写基本信息和经历。经历可折叠、复制、上下移动；新增空条目自动聚焦。日期支持年月及“至今”，旧日期文本仍保留。
3. 在版式中调整字号、栏目顺序和显示状态。排序也可用键盘上下方向键；照片支持裁剪、旋转、压缩、删除。
4. 在“更多”菜单查看本机保存状态。“预览模式”直接展示当前内容，离线也可用；预览中可缩放或定位回编辑栏目。
5. 点击“导出”，选择格式并确认文件名。手机上通过“编辑模式 / 预览模式”切换工作区。

### 保存、恢复和多份简历

本机保存约在编辑停止 350ms 后执行。无需登录，不上传简历。看到“本机保存失败”时请先导出 JSON 备份。不同浏览器、设备和网站地址的数据彼此独立；清除浏览器数据后刷新，页面会重新显示样例模板。

工具栏提供撤销、重做。输入框中的系统文字撤销保留原生行为；输入框外可用 Cmd/Ctrl+Z、Cmd/Ctrl+Shift+Z 操作整份简历，Cmd/Ctrl+S 尝试保存。

删除条目后可直接撤销；导入、重置前会创建恢复点。通过“更多 → 查看恢复点”恢复或下载旧稿。每份简历最多 5 个恢复点，全部恢复点按 UTF-16 字符估算限制为 2 MiB；浏览器自身容量限制仍可能先发生。无法创建恢复点时不会继续替换原稿。

点击“更多 → 管理简历”，可命名、新建、复制、切换简历。草稿和恢复点按稳定 ID 隔离；换设备前可先下载 JSON 备份。恢复时支持确认替换或另存为新简历。

### 网页预览

“网页预览”打开本机当前稿，可缩放、导出并返回编辑。此地址不用于分享个人内容，其他人打开网站时会看到他们自己浏览器中的数据。

### 两种导出

| 模式 | 操作结果 | 用途 |
| --- | --- | --- |
| A4 PDF（文字内容） | 打开浏览器打印对话框，可另存为 PDF；通常保留可复制文字 | 打印、投递。 |
| 长页 PDF（图片内容） | 下载包含整页截图的 PDF，不是 PNG/JPG | 连续浏览、展示整体排版。 |

A4 打印建议选择另存为 PDF、A4、100% 缩放并关闭页眉页脚。文件名是建议值，实际保存名称由浏览器打印窗口决定。首次导出说明可以关闭并记住。

导出前会提醒姓名为空、联系方式均隐藏或超长条目。超长条目允许自然跨页；照片加载后会重新测量。最终 A4 打印结果仍需在目标浏览器确认，特别是超长经历、长网址和字体替换。

JSON 备份保留内容和配置，用于继续编辑；PDF 用于阅读。照片导入支持 JPG、PNG、WebP，最大 10 MB，裁剪后按 480×600 压缩保存。

## 2. 本地开发与验证

在项目根目录执行：

```bash
pnpm install
pnpm dev
```

访问 [本地编辑器](http://127.0.0.1:45221)。端口固定为 45221；如果被占用，先检查是否已经运行了本项目的开发服务。

Vite 的 Cloudflare 插件提供本地 Worker 和 D1 开发环境。当前版本不读写 D1，无需执行数据库迁移。

| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | 启动本地开发服务。 |
| `pnpm run build` | 类型检查并构建发布文件。 |
| `pnpm preview` | 构建后预览。 |
| `pnpm test` | 执行 Vitest 测试。 |
| `pnpm check` | 类型检查、测试和生产构建。 |
| `pnpm db:generate` | 根据 Drizzle 表定义生成迁移文件。 |
| `pnpm db:migrate` | 将迁移应用到本地 D1。 |
| `pnpm cf-typegen` | 根据 Cloudflare 配置重新生成 Worker 环境类型。 |

测试能验证分页计算、数据整理和保存逻辑，但不能代替浏览器中的实际排版与打印检查。详细覆盖范围见 [架构：测试与阅读顺序](architecture.md#chapter-12)。

## 3. Cloudflare 部署

当前仓库的 [wrangler.toml](../wrangler.toml) 已配置 Worker 名称、前端资源目录和真实 D1 数据库 ID。向现有项目发布时，确认账号和配置后直接使用：

```bash
pnpm check
pnpm run deploy
```

`pnpm run deploy` 会再次构建，再调用 Wrangler 发布。不要写成 `pnpm deploy`，后者可能调用 pnpm 自带的同名命令。

部署到新项目时，使用 `pnpm exec wrangler login` 登录 Cloudflare，修改 Worker 名称，并可移除 `wrangler.toml` 中闲置的 D1 绑定；无需创建数据库或邮件服务。

历史数据库和迁移文件保留，但当前代码不读写它们。旧云端接口返回 410；`/api/health` 返回 `storage: "browser"`。发布后检查编辑、本机预览、JSON 导入导出和 PDF。

## 4. 修改模板与定位代码

### 修改自己的简历

在编辑器修改，或导入自己的 JSON。导出 JSON 可以保留内容、版式和内嵌照片，便于以后恢复。

### 修改项目默认模板

统一编辑 [public/sample-resume.json](../public/sample-resume.json)。[seed.ts](../src/shared/seed.ts) 从这里读取示例，供重置和默认回退、首次打开使用。

模板更新后，已有本地草稿仍保留原内容。要载入新模板，可使用编辑器“重置示例”；操作前按需要导出当前草稿。

### 按修改内容找文件

| 要修改什么 | 从哪里开始 |
| --- | --- |
| 增加字段、兼容旧 JSON | [schema.ts](../src/shared/schema.ts)、[EditorForms.tsx](../src/app/components/editor/EditorForms.tsx) |
| 简历显示、联系方式与版式 | [ResumeDocument.tsx](../src/app/components/resume/ResumeDocument.tsx)、[index.css](../src/app/index.css) |
| 本地草稿、备份与恢复 | [useResume.ts](../src/app/hooks/useResume.ts)、[draftStore.ts](../src/app/lib/draftStore.ts) |
| 后端接口和数据库结构 | [worker/index.ts](../src/worker/index.ts)、[db/schema.ts](../src/db/schema.ts) |
| 分页或 PDF 导出 | [架构：排版](architecture.md#chapter-8)、[架构：导出](architecture.md#chapter-9) |

接口清单、表结构和数据流统一见 [技术架构](architecture.md)，这里不另维护一份。

## 5. 常见问题

**模板改了，为什么页面没变？** 页面可能在使用已有本地草稿或云端记录。更新模板不是覆盖用户数据；要使用新示例，需要在编辑器重置或导入。

**换设备怎么继续编辑？** 在原设备导出 JSON，再到新设备导入。网站不提供账号、云端同步或公开分享。

**清空浏览器数据后能找回吗？** 本机草稿和恢复点会一起清除；可以导入此前导出的 JSON，否则刷新后将显示样例模板。

**长图 PDF 为什么不能复制文字？** 当前长图路径先把简历变成图片，再放入 PDF。需要保留文字时使用 A4 打印路径。

**隐藏联系方式，是否等于把数据删掉？** 不等于。隐藏只影响展示，原值仍可能保存在 浏览器草稿和导出的 JSON 里。

**完整的技术解释看哪里？** 系统如何配合看技术架构；“面试怎么说”和名词解释看面试准备。两份文档顶部都有章节目录。
